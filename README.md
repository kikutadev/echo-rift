# ECHO RIFT

Autonomous game benchmark created from a single product goal: **make a game that stays interesting for about 30 minutes without human improvement instructions**.

## Core loop

One run lasts eight minutes. Movement is the main decision: every few seconds an ECHO replays the player's previous three seconds of movement and firing, so the path used to escape now becomes delayed offensive positioning. The player auto-fires, uses a phase dash, collects signal shards, and chooses one of three mutations at each level.

A 30-minute session is intended to be several short runs with different seeds and builds rather than one padded run.

## Autonomous acceptance

The benchmark does not treat build-passing as proof of fun. It uses cheaper observable proxies, then keeps the remaining uncertainty explicit.

- Deterministic simulation: same seed + inputs must produce the same metrics.
- Skill gradient: idle < random < body-only avoidance < projectile-aware avoidance.
- Build diversity: at least three distinct mutation strategies must remain viable across seeded runs.
- Pacing: early, middle, and late phases must all generate combat and progression rather than collapse into a dead period.
- Browser acceptance: real Chrome must load and play without runtime errors on desktop and 390×844 mobile viewports.
- Visual acceptance: gameplay must occupy the mobile screen; portrait uses a player-following crop instead of letterboxing.

simulation-report.json is generated by the current simulation pass. It is evidence about balance and learnability proxies, **not proof that the game is subjectively fun**.

## Commands

- node scripts/test.mjs — deterministic core checks.
- node scripts/simulate.mjs — seeded bot and build evaluation.
- node scripts/qa.mjs — real-Chrome rendered QA; requires Chrome host permissions.
- node scripts/qa-touch.mjs — true touch event regression in mobile Chrome.
- node scripts/qa-density.mjs — viewport enemy density, midgame visual snapshot and frame timing.

Open index.html through a local HTTP server to play.


## Mobile-first swarm update (2026-10-08)

- Enemies appear in waves near the visible camera area; the game maintains a time-dependent active swarm and caps it at 110.
- Portrait camera framing now leads toward the battlefield near world boundaries without zoom changes.
- Each enemy type has a differentiated shape/face. Local separation prevents the swarm from collapsing into one illegible blob.
- The main gun fires a three-way spread, kills emit short-range splash damage, and ECHO bullets replay the recorded shots.
- Impacts, kills, ECHO spawns and dash-rifts have short trails, particles, rings, hit numbers, mild camera shake and throttled synthesized audio.
- Rendering uses bounded effect queues, capped particles/pickups and batched item drawing. Zoom gestures remain disabled during gameplay.
- The density QA requires >=20 enemies in the opening seconds and >=20 visible enemies in the simulated midgame mobile viewport at >=40 measured fps on the test host.

The dash-specialized build remains weaker in bot survival than weapon/ECHO builds; the current benchmark records rather than conceals that limitation.
